# 02. 데이터 소스 조사 (API / 크롤링 가능 여부)

> **결론 (2026-11-21): 수집에 쓸 수 있는 데이터 소스를 찾지 못해 데모 시뮬레이터로 전환했습니다.** 아래는 전환 전에 조사한 기록입니다. 시뮬레이터는 `supabase/002_simulator.sql`, 설계는 `04_시스템설계.md` 3절에 있습니다.
> - 아래 3절의 수집 원칙(robots.txt 준수, 낮은 빈도, 출처 링크 등)은 나중에 실제 수집기를 붙일 때 그대로 적용합니다.
> - 확인용 스크립트 `scripts/check_source.py`는 새 소스를 찾게 되면 다시 쓸 수 있도록 남겨 둡니다.
> - 시뮬레이터는 실제 업체의 가격을 주장하지 않도록 **가상 브랜드(STRIDEON, NORTHLINE 등)와 가상 쇼핑몰(데모몰A~C)**만 씁니다.

> 조사일: 2026-11-12

## 2. 소스별 상세

### 2.1 무신사 (1순위)
- **공식 API:** 없음
- **수집 방법:** 상품 목록 페이지는 화면을 그릴 때 브라우저가 별도의 JSON 데이터를 받아옵니다. 크롬 개발자도구(F12) → Network 탭 → Fetch/XHR 필터로 그 요청 URL을 찾아, 파이썬 `requests`로 같은 요청을 보냅니다.
- **필요한 필드:** 상품번호, 상품명, 브랜드, 정가, 판매가(할인가), 할인율, 이미지 URL, 카테고리, 품절 여부
- **위험:** 요청 URL 형식이 예고 없이 바뀔 수 있다. 너무 자주 요청하면 차단된다.
- **참고:** 무신사 검색 결과를 수집하는 외부 유료 도구(Apify)가 있어, 직접 수집이 막힐 때 비상용으로 쓸 수 있습니다 ([Apify Musinsa Scraper](https://apify.com/getascraper/musinsa-scraper.md)).

### 2.2 29CM (2순위)
- 무신사와 같은 방식(내부 JSON 요청 찾기)으로 접근합니다.
- 브랜드와 상품 구성이 무신사와 일부 겹쳐 **플랫폼 간 비교** 기능을 보여주기에 좋습니다.

### 2.3 Shopify 기반 브랜드몰 (3순위, 가장 안정적)
- Shopify로 만든 쇼핑몰은 대부분 `https://<도메인>/products.json?limit=250&page=1` 주소에서 상품 목록을 JSON으로 공개합니다.
- `variants[].price`는 판매가, `variants[].compare_at_price`는 정가(할인 전 가격)입니다.
- **장점:** 구조가 표준이라 수집기 하나로 여러 브랜드몰을 처리할 수 있습니다.
- **할 일:** 신발·의류 브랜드 중 Shopify를 쓰는 곳을 3~5개 찾습니다. 주소 뒤에 `/products.json`을 붙여 JSON이 나오면 Shopify입니다.

### 2.4 사용 불가 확인
- **네이버 쇼핑 검색 API:** 네이버 검색 API가 NAVER API HUB로 옮겨가면서 **쇼핑, 책, 전문자료 검색 API는 이관되지 않고 2026-07-31에 종료**되었습니다. 대체 API도 없습니다. ([waffleboard 이관 가이드](https://waffleboard.io/blog/naver-search-api-hub-migration-guide), [MiniBiz 정리](https://minibiz.kr/%EB%84%A4%EC%9D%B4%EB%B2%84-api-hub-%EB%84%A4%EC%9D%B4%EB%B2%84-%EA%B0%9C%EB%B0%9C%EC%9E%90%EC%84%BC%ED%84%B0-api-%EB%B0%8F-%EB%AC%B4%EB%A3%8C-%EC%9A%94%EA%B8%88%EC%A0%9C-%EB%B3%80%EA%B2%BD/), [Keyword Cockpit](https://keywordcockpit.com/naver-api-hub-migration/))

## 3. 수집 원칙 (윤리와 법)

| 원칙 | 내용 |
|---|---|
| robots.txt 준수 | 수집 전에 각 사이트의 `/robots.txt`를 확인하고, 금지된 경로는 수집하지 않는다 |
| 낮은 빈도 | 하루 2회 수집, 요청 사이에 1~2초 대기, 동시 요청은 하지 않는다 |
| 최소 수집 | 가격 판단에 필요한 정보만 모은다. 리뷰나 개인정보는 수집하지 않는다 |
| 이미지 | 이미지 파일을 저장하지 않고 원본 URL로만 보여준다 |
| 출처와 링크 | 모든 상품에 "원본 쇼핑몰에서 보기" 링크를 단다 |
| 목적 명시 | README와 사이트 하단에 "비상업적 학습 프로젝트"라고 밝힌다 |
| 중단 대응 | 사이트가 수집 중단을 요청하거나 차단하면 즉시 해당 수집기를 끈다 |

## 4. "있는 상품 전부"의 현실적 범위

- 무신사 전체 상품은 수백만 개 규모라 무료 DB와 수집 시간 안에 담을 수 없습니다.
- 그래서 범위를 **"신발·의류 카테고리 중 현재 할인 중인 상품 전부"**로 정합니다. 한 번 수집한 상품은 할인이 끝나도 가격을 계속 추적합니다. 그래야 "정가로 돌아갔다"는 기록이 쌓이고, 신뢰도 판정의 근거가 됩니다.
- 예상 규모는 소스당 1~3만 개입니다. 용량 계산은 `05_DB설계.md` 5절에 있습니다.

## 6. 확인용 파이썬 코드 (뼈대)

```python
# scripts/check_source.py : 응답 구조 확인용
import requests, json

URL = "개발자도구에서 찾은 목록 JSON 주소"
headers = {"User-Agent": "Mozilla/5.0 (TagCheck student project)"}
res = requests.get(URL, headers=headers, timeout=10)
print(res.status_code)
print(json.dumps(res.json(), ensure_ascii=False, indent=2)[:2000])
```
