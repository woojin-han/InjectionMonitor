# 03. 요구사항 정의서

우선순위: **M** = 필수(Must), **S** = 있으면 좋음(Should), **C** = 시간 나면(Could)

## 1. 기능 요구사항

### 1.1 회원 (AUTH)
| ID | 요구사항 | 상세 | 우선순위 |
|---|---|---|---|
| AUTH-01 | 회원가입 | 이메일, 비밀번호(8자 이상, 영문+숫자), 닉네임 입력. 이메일 중복 확인 | M |
| AUTH-02 | 로그인 | 이메일과 비밀번호로 로그인. 실패하면 오류 문구 표시 | M |
| AUTH-03 | 로그아웃 | 헤더 메뉴에서 로그아웃 | M |
| AUTH-04 | 로그인 유지 | 브라우저를 다시 열어도 로그인 상태 유지 | M |
| AUTH-05 | 비밀번호 재설정 | 이메일로 재설정 링크 발송 (Supabase 기본 기능) | S |
| AUTH-06 | 접근 제한 | 찜, 관심 상품, 알림은 로그인한 사용자만 쓸 수 있다. 비로그인 상태에서 누르면 로그인 화면으로 이동 | M |

### 1.3 상품 상세 (DETAIL)

|---|---|---|---|

| DETAIL-02 | 가격 그래프 | 기간 선택(7일/30일/전체). 정가선과 역대 최저가선을 함께 표시 | M |
| DETAIL-03 | 할인 신뢰도 | 등급, 정가 판매일 비율, 실질 할인율, 계산 근거 설명 | M |

### 1.5 관심 상품과 알림 (WATCH / NOTI)
| ID | 요구사항 | 상세 | 우선순위 |
|---|---|---|---|
| WATCH-01 | 관심 상품 등록 | 상세 화면에서 목표가 입력 (기본값은 역대 최저가) | M |
| WATCH-02 | 알림 조건 선택 | ① 목표가 이하 ② 역대 최저가 갱신 ③ 품절 후 재입고 (여러 개 선택) | M (①②), C (③) |
| WATCH-03 | 관심 상품 관리 | 목록에서 목표가 수정과 삭제 | M |
| NOTI-01 | 알림 생성 | 수집 직후 조건을 검사해 알림을 만든다. 같은 조건은 24시간에 1번만 | M |
| NOTI-02 | 알림 표시 | 헤더 종 아이콘에 읽지 않은 개수 배지, 누르면 알림 목록 | M |
| NOTI-03 | 읽음 처리 | 알림을 누르면 읽음으로 바뀌고 상품 상세로 이동. "모두 읽음" 버튼 | M |
| NOTI-04 | 실시간 반영 | 페이지를 연 상태에서도 새 알림이 바로 뜬다 (Supabase Realtime) | S |

### 1.6 데이터 수집 (CRAWL)
| ID | 요구사항 | 상세 | 우선순위 |
|---|---|---|---|
| CRAWL-01 | 자동 수집 | 하루 2회 (09:00, 21:00 KST) 자동 실행 | M |
| CRAWL-02 | 가격 기록 | 상품별로 하루 1건 가격 기록 저장(그날 수집한 값 중 최저가). 가격이 같아도 기록한다 (정가 판매일 계산용) | M |
| CRAWL-03 | 상품 갱신 | 새 상품은 추가하고, 기존 상품은 현재가, 품절 여부, 최종 수집 시각을 갱신 | M |
| CRAWL-04 | 실패 대응 | 한 소스가 실패해도 다른 소스는 계속 수집한다. 실행 기록(성공·실패 수) 저장 | M |
| CRAWL-05 | 통계 갱신 | 수집 후 역대 최저가, 신뢰도 점수를 다시 계산 | M |
| CRAWL-06 | 품번 정규화 | 상품명에서 브랜드, 모델명, 품번을 뽑아 같은 상품끼리 묶는다 (OpenAI 사용) | S |

## 2. 비기능 요구사항

| ID | 분류 | 요구사항 |
|---|---|---|
| NFR-01 | 비용 | 모든 구성 요소를 무료 요금제 안에서 운영한다 (월 0원) |
| NFR-02 | 성능 | 목록 첫 화면이 2초 안에 표시된다 |
| NFR-03 | 반응형 | 360px(모바일)부터 1440px(PC)까지 화면이 깨지지 않는다 |
| NFR-04 | 보안 | 비밀번호는 Supabase Auth가 암호화해 저장한다. 다른 사람의 찜과 알림은 DB 단계(RLS)에서 막는다. API 키는 GitHub Secrets와 환경변수로만 관리하고 코드에 넣지 않는다 |
| NFR-05 | 신뢰성 | 수집 실패가 3회 연속되면 관리자 화면(또는 Actions 기록)에서 확인할 수 있다 |
| NFR-06 | 정직성 | 수집 기간이 7일 미만인 상품은 신뢰도를 "데이터 부족"으로 표시한다 |
| NFR-07 | 접근성 | 가격 상승과 하락을 색만으로 구분하지 않고 ▲▼ 기호를 함께 쓴다. 대비율은 4.5:1 이상 |
| NFR-08 | 유지보수 | 수집기는 소스마다 파일 하나로 분리한다 (어댑터 구조) |

## 3. 용어 정의

| 용어 | 정의 |
|---|---|
| 정가 | 쇼핑몰이 표시한 할인 전 가격 |
| 현재가 | 가장 최근 수집한 판매가 |
| 표시 할인율 | (정가 − 현재가) ÷ 정가. 쇼핑몰이 보여주는 할인율 |
| 기준가 | 최근 30일 판매가의 **중앙값**. 실제로 "보통 이 가격에 팔리던 값" |
| 실질 할인율 | (기준가 − 현재가) ÷ 기준가. 택체크가 보여주는 진짜 할인율 |
| 역대 최저가 | 수집을 시작한 뒤 기록된 가장 낮은 판매가 |
| 정가 판매일 비율 | 정가로 팔린 날 수 ÷ 수집한 날 수 |
| 신뢰도 등급 | 진짜 할인 / 보통 / 부풀림 의심 / 데이터 부족 (계산식은 `04_시스템설계.md` 4절) |
