# 01. 프로젝트 기획서

> 대림대학교 전공심화(1년) 과정 · 실무프로젝트2 기말 프로젝트
> 작성일: 2026-11-12 · 작성자: 1인 개발

## 1. 프로젝트 개요

| 항목 | 내용 |
|---|---|
| 프로젝트명 | **택체크 (TagCheck)** : 신발·의류 진짜 할인 모아보기 |
| 이름 뜻 | 가격**택**을 **체크**한다. 매장 가격택에 붙은 할인 스티커가 진짜인지 확인한다는 뜻 |
| 한 줄 소개 | 여러 쇼핑몰의 신발·의류 할인가를 모으고, **실제 판매가 기록**과 비교해 할인이 진짜인지 보여주는 웹 서비스 |
| 형태 | 반응형 웹 (PC와 모바일 브라우저) |
| 개발 인원 | 1명 |
| 기간 | 2026-11-12 ~ 2026-11-30 (약 3주) |
| 제출 | GitHub 저장소 (코드, 문서, 목업) |

## 2. 기획 배경 (문제 정의)

1. **할인율 부풀리기.** 일부 쇼핑몰은 정가를 높게 표시한 뒤 "70% 할인"처럼 보여줍니다. 그런데 실제로는 그 정가로 판매된 적이 거의 없어 할인율을 믿기 어렵습니다.
2. **플랫폼마다 가격이 다름.** 같은 신발이라도 무신사, 29CM, 브랜드 공식몰 가격이 다르고, 할인 시기도 다릅니다. 하나씩 찾아보기가 번거롭습니다.
3. **"지금이 싼가?"를 알 수 없음.** 쇼핑몰은 현재 가격만 보여줍니다. 지난 가격이나 역대 최저가는 알려주지 않습니다.

## 3. 목표

| 구분 | 목표 |
|---|---|
| 사용자 목표 | 이 할인이 진짜인지, 지금 사도 되는지 **3초 안에** 판단할 수 있게 한다 |
| 기능 목표 | 현재가, 정가, 역대 최저가, 가격 그래프, 할인 신뢰도, 찜, 관심 상품(목표가 알림)을 제공한다 |
| 기술 목표 | 서버 없이 무료 클라우드만으로 **매일 자동 수집, DB 저장, 웹 배포**를 구성한다 |
| 평가 목표 | OpenAI 활용, 완성도, 난이도의 세 기준을 모두 문서와 기능으로 보여준다 |

## 4. 타깃 사용자 (페르소나)

| 페르소나 | 특징 | 핵심 니즈 |
|---|---|---|
| 대학생 김민수 (23) | 무신사를 자주 이용하고, 세일 기간에 몰아서 산다 | "70% 할인이 진짜야?" |
| 직장인 이지은 (29) | 특정 운동화 모델을 기다린다 | "원하는 가격이 되면 알려줘" |
| 리셀 입문자 박준호 (25) | 여러 플랫폼 가격을 비교한다 | "어디가 제일 싸?" |

## 5. 핵심 기능 요약

| 기능 | 설명 | 우선순위 |
|---|---|---|
| 할인 상품 모아보기 | 여러 플랫폼의 할인 상품을 한 화면에서 보고 필터와 정렬을 쓸 수 있다 | 필수 |
| 가격 정보 3종 | **현재 할인가, 정가, 역대 최저가**를 함께 표시한다 | 필수 |
| 가격 그래프 | 수집 기간 동안의 가격 변화를 그래프로 보여준다 | 필수 |
| 할인 신뢰도 | 정가로 판매된 기록을 바탕으로 "진짜 할인 / 보통 / 부풀림 의심"을 판정한다 | 필수 (차별점) |
| 로그인 | 이메일과 비밀번호로 회원가입하고 로그인한다 | 필수 |
| 찜 | 하트를 눌러 저장하고 찜 목록을 본다 | 필수 |
| 관심 상품 (목표가 알림) | 목표가를 정해 두면, 가격이 그 아래로 내려가거나 역대 최저가가 갱신될 때 웹 안에서 알림을 띄운다 | 필수 |
| 플랫폼 간 가격 비교 | 같은 모델의 플랫폼별 가격을 비교한다 (품번 기준) | 선택 |
| AI 할인 요약 | OpenAI로 "지금 사도 될까?" 한 줄 요약을 만든다 | 선택 (평가 항목) |

## 6. 경쟁 서비스 분석

| 서비스 | 장점 | 한계 | 택체크의 차별점 |
|---|---|---|---|
| 무신사 등 쇼핑몰 자체 할인 | 상품이 많다 | 정가 대비 할인율만 보여준다 | **실제 판매가 대비 할인율**을 보여준다 |
| 다나와·에누리 | 가격 비교에 강하다 | 패션 카테고리가 약하고, 정가 부풀리기는 판정하지 않는다 | 패션에 특화하고 신뢰도를 판정한다 |
| 폴센트 (가격 추적) | 가격 알림이 있다 | 주로 쿠팡 위주다 | 패션 플랫폼 위주로 다룬다 |
| 해외 Keepa, CamelCamelCamel | 가격 그래프의 대표 서비스 | 국내 패션몰은 지원하지 않는다 | 국내 패션몰을 대상으로 한다 |

## 7. 범위

### 포함 (MVP)
- 데이터 소스 2~3곳 자동 수집 (근거는 `02_데이터소스조사.md`)
- 하루 2회 가격 기록 저장
- 웹: 목록, 상세, 로그인, 찜, 관심 상품, 알림
- 할인 신뢰도 계산과 OpenAI 요약

### 제외
- 결제와 구매 대행 (상품은 원래 쇼핑몰 링크로 연결)
- 모바일 앱, 이메일·푸시 알림 (알림은 웹 안에서만)
- 수집 이전의 과거 가격 (**지금부터 수집한 기록만** 보여준다. 결정사항 8-a)

## 8. 주요 결정사항

| 번호 | 결정 | 이유 |
|---|---|---|
| D1 | 웹으로 만든다 | 1인 개발에 기간이 짧다 |
| D2 | 별도 서버 없이 Vercel, Supabase, GitHub Actions를 쓴다 | 서버가 없고 비용을 0원으로 맞춰야 한다 |
| D3 | 역대 최저가는 직접 수집한 기록만으로 계산한다 | 데이터를 정직하게 다룬다. 화면에 "2026-11-xx부터 수집"을 표시한다 |
| D4 | 알림은 웹 안에서만 띄운다 | 요구사항 10번 |
| D5 | 로그인은 이메일과 비밀번호로 한다 (Supabase Auth) | 요구사항 11번 |
| D6 | "있는 상품 전부" 수집하되 **신발·의류의 할인 상품**으로 한정한다 | 무료 DB 용량(500MB)과 수집 시간 때문이다. 계산은 `05_DB설계.md`에 있다 |

## 9. 기대 효과
- 정가 부풀리기를 숫자로 드러내 소비자가 합리적으로 구매하도록 돕는다.
- 수집, 저장, 분석, 시각화, 인증, 알림까지 웹 서비스의 전 과정을 1인이 구현하는 경험을 쌓는다.
